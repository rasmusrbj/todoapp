# todoapp

A todo app built as a contract-first stack: one Protobuf contract, four consumers.

```
proto/todo/v1/          the contract — enums, messages, four services
backend/                Python 3.12+, connect-python (ASGI), psycopg3, raw SQL
backend/src/todoapp/cli/  the `todoapp` CLI — a pure API client
web/                    Next.js 16, React 19, Tailwind 4, next-intl (da/en)
apple/                  native SwiftUI iOS app, connect-swift — see apple/AGENTS.md
```

Nothing is generated by hand. `make generate` writes `backend/gen/`, `web/src/gen/` and
`apple/gen/` from `proto/`. All three are gitignored.

Codegen is **one buf config per consumer** (`buf.gen.backend.yaml`, `buf.gen.web.yaml`,
`buf.gen.swift.yaml`), and that split is load-bearing: every config uses `clean: true`, so
a run that fails part-way leaves nothing behind. Web and iOS use **local** plugins
(`protoc-gen-es`, `protoc-gen-swift`) and work offline; only the Python plugins are
remote, because `connect-python` ships no local binary — and the BSR rate-limits remote
plugins, so `make build` deliberately depends on `generate-web` alone rather than putting
a network call on the hot path of `make check`.

## The five rules that shape everything

1. **The proto is the source of truth.** Enum labels, error reasons, and field names all
   come from it. Change the contract first, run `make generate`, then follow the type
   errors.

2. **Every closed set is an enum, end to end.** A proto enum has a matching PostgreSQL
   enum type, a derived Python codec, and a localized display name in *both* the web
   catalogues and the CLI. See "Adding an enum value" below — there are five places, and
   `tests/test_enum_parity.py` fails if you miss the database.

3. **Authorization lives in SQL.** Every read is filtered by an `EXISTS` over
   `list_members` inside the query. There is no shape of request that returns a list the
   caller cannot see. Clients never re-implement the rules; they only hide controls the
   API would refuse.

4. **No raw enum, no English string, ever reaches a user.** The server sends
   `ErrorReason` and PostgreSQL labels; clients translate. A missing translation shows as
   `⚠️ key` in development, which is the point.

5. **Migrations are forward-only and checksummed.** Editing an applied migration makes
   `todoapp-migrate` refuse to run. Write a new one.

## Getting it running

```bash
make setup          # install, generate, create databases, migrate, seed
make dev            # backend on :8081, web on :3000
make test           # 120 backend tests against a real PostgreSQL
make check          # what CI would run: lint, test, build
```

`make seed` **asks** which email and password to create the admin account with, and writes
the pair to `.demo-account.env` (gitignored) for `make cli-coverage` and the iOS
end-to-end targets to read. Nothing is hardcoded — this repository is public. Two
collaborators come with it: `partner@example.com` and `colleague@example.com`, same
password. Non-interactively: `--email`/`--password`, or `TODOAPP_DEMO_EMAIL` /
`TODOAPP_DEMO_PASSWORD`. With neither and no terminal it refuses rather than defaulting.

The backend is on **8081**, not 8080 — 8080 collides with WhatsApp Desktop on macOS.

## Adding an enum value

Six edits, in this order. Skipping any of the first four breaks the build; skipping the
last two breaks a client's UI silently, which is why both have a parity test.

1. `proto/todo/v1/enums.proto` — add the value. Keep declaration order meaningful:
   `TaskPriority` runs least → most urgent so `ORDER BY priority DESC` works, and
   `MemberRole` runs most → least privileged.
2. `make generate`.
3. A new migration: `ALTER TYPE task_status ADD VALUE 'deferred';` — and note that
   `ALTER TYPE ... ADD VALUE` cannot run inside a transaction block in PostgreSQL below
   12, so check before wrapping it.
4. `web/messages/da.json` and `en.json` — add the display name under `enums.<namespace>`,
   keyed by the **full proto value name** (`TASK_STATUS_DEFERRED`).
5. `backend/src/todoapp/cli/display.py` — the same string, both locales, kept in parity
   with the web catalogues.
6. iOS: `apple/Core/Domain/EnumDisplay.swift` (the switch stops compiling until you add
   the case — Swift gives compile-time exhaustiveness the other two clients cannot) and
   the matching key in `apple/Apps/Todo/Resources/Localizable.xcstrings`, both languages.

Nothing in Python or TypeScript maps values by hand: `EnumCodec` derives the PostgreSQL
label from the descriptor, and `enumToJson` derives the translation key. Swift maps them
explicitly, on purpose — the exhaustive switch is a stronger guarantee than a runtime
lookup that would fall back to a placeholder.

Verify all of it: `make test` (PostgreSQL parity), `cd web && pnpm check:messages`, and
`make ios-test` (which reads the *compiled* da/en bundles, not the JSON).

## Adding an RPC

1. Add the method and its request/response to the right `proto/todo/v1/*.proto`.
2. `make generate`.
3. Implement it on the service class in `backend/src/todoapp/services/`. Start with
   `require_principal(ctx)`, then a `permissions.require_*` check, then the work.
4. Add repository functions in `backend/src/todoapp/repositories/` — plain SQL, no ORM,
   the connection as the first argument.
5. Map rows to proto in `backend/src/todoapp/services/mappers.py`. Never build a message
   inline in a handler.
6. Tests in `backend/tests/` — the happy path *and* the authorization boundary.
7. Web: a Server Action in `web/src/app/actions/`, then the UI.
8. CLI: a subcommand in `backend/src/todoapp/cli/commands/`.

## Where the rules actually live

| Concern | File |
|---|---|
| Enum ↔ PostgreSQL mapping | `backend/src/todoapp/domain/enums.py` |
| Request validation, field limits | `backend/src/todoapp/domain/validation.py` |
| Recurrence arithmetic (month clamping) | `backend/src/todoapp/domain/recurrence.py` |
| List permissions (read/comment/write/own) | `backend/src/todoapp/auth/permissions.py` |
| Password policy, Argon2 parameters | `backend/src/todoapp/auth/passwords.py` |
| Session tokens (opaque, SHA-256 stored) | `backend/src/todoapp/auth/tokens.py` |
| Error reasons → codes | `backend/src/todoapp/errors.py` |
| Row → proto | `backend/src/todoapp/services/mappers.py` |
| Web enum tokens and role helpers | `web/src/lib/enums.ts` |
| Web error → localized message | `web/src/lib/errors.ts` |
| Session cookie handling | `web/src/lib/session.ts` |

## Things that will bite you

- **`buf generate` has `clean: true`.** Its `out` directories are wiped on every run, so
  they must contain *only* generated code. This is why Python goes to `backend/gen/` and
  not `backend/src/`. Never point a plugin at a directory holding hand-written files.
- **`import_extension=none` is required** for the TypeScript plugin. Next.js resolves
  with `moduleResolution: bundler` and cannot follow a `.js` specifier pointing at a
  `.ts` file.
- **psycopg collapses repeated named parameters** into one positional parameter. A value
  used once as a `uuid` column and once inside a `CASE` branch needs an explicit cast at
  every site, or PostgreSQL raises `AmbiguousParameter`.
- **Task positions are not dense.** `create` inserts at `min(position) - 1`, so values go
  negative. `tasks.move` renumbers the whole list rather than nudging neighbours — do not
  "optimise" that back into an offset update.
- **proto3 JSON omits defaults.** `false`, `0`, and empty repeated fields are absent from
  a response, not present-and-empty. Tests must use `.get(key, default)`.
- **A Server Action file can only export async functions.** Sync helpers belong in
  `lib/`, not next to the actions that use them.
- **`redirect()` throws.** Call it outside the `try`, or the catch reports the navigation
  as a failure.

## The CLI

A pure API client — it speaks Connect over HTTP and never touches the database, so
anything it can do is something the API genuinely exposes.

```bash
todoapp auth login --email you@example.com
todoapp lists ls
todoapp tasks list --open --overdue
todoapp tasks get 4f2c              # any unique id prefix works
todoapp tasks add "Køb mælk" --list ind --due tomorrow --priority high
todoapp tasks done 4f2c
todoapp tasks list --json | jq '.tasks[].title'
```

Every command takes `--json`, `--locale da|en`, and `--server`. Config lives in
`~/.config/todoapp/config.json` at mode 0600.

`--json` is machine-readable on **every** path, which is what makes the CLI usable by an
agent: on success the payload goes to stdout and stderr is empty; on any failure stdout is
empty and stderr carries exactly one `{"error": {...}}` object with `reason` (an
`ErrorReason` name), and optionally `field`, `metadata` and `hint`. Branch on `reason` —
`message` is localized prose. Exit codes: `0` ok, `1` failed, `2` bad usage, `3` not
signed in or not allowed. `tests/test_cli_json_contract.py` pins all of it, including that
an argparse usage error is JSON too (it exits before any handler, so it needed its own
parser subclass).

## The iOS app

Native SwiftUI, connect-swift, the Happenings design system in its native form.
`apple/AGENTS.md` is the full guide — read it before touching `apple/`. The parts that
surprise people:

```bash
make ios-project      # regenerate the Xcode project (project.yml is the truth)
make ios-build
make ios-test         # hermetic: 29 unit tests + a launch smoke test
make ios-test-live    # end-to-end against `make dev-backend`
make ios-screenshots  # every screen as a PNG
make ios-device       # sign and install on a paired iPhone
```

Device builds need your own Apple team in a gitignored `apple/Signing.local.xcconfig` —
`make ios-signing TEAM=…`. A phone also needs `make dev-backend-lan` — `make dev-backend` binds loopback, which a device cannot
reach, and on a device `127.0.0.1` is the phone itself. `make ios-device` bakes the Mac's
Bonjour name into Info.plist so a changing DHCP lease does not break it.

- **The app follows the account's language**, not the device's — `User.locale` is stored
  server-side so the phone and the web agree. A UI test cannot override it with
  `-AppleLanguages` after sign-in; assert on accessibility identifiers instead.
- **The session token is opaque, not a JWT.** `RefreshSession` authenticates with the
  token it is replacing, so renewal goes out on an interceptor-free client with the
  header set explicitly. A transient renewal failure keeps the existing token — only an
  outright rejection signs the user out.
- **SwiftProtobuf renames fields that collide with its accessors**: `clear_due_at` →
  `clearDueAt_p`, `clear_assignee` → `clearAssignee_p`, `has_more` → `hasMore_p`. The
  un-suffixed name is a compile error, which is the good outcome.
- **`buf.gen.yaml` writes `apple/gen/` with `clean: true`** — the same trap as the other
  outputs: never point it at a directory that also holds hand-written source.

## Design system

The web app follows the Happenings system — invoke the `happenings-design` skill before
touching UI. In short: borders not shadows, `rounded-xl` on cards, `cursor-pointer` and a
scale-down press on everything clickable, Font Awesome Pro only (no Lucide), light and
dark for every view, and every string through `next-intl`.

Components come from `ui.happenings.social`. Two of them needed local fixes worth knowing
about: `dialog.tsx` shipped a Lucide icon and a hardcoded "Close" (both replaced), and
`calendar.tsx` targets react-day-picker v9 — the version is pinned for that reason.
